# ModelDock development

- Keep app logic in TypeScript and the UI in React. The gateway and credentials live in the main process, with a narrow preload bridge.
- Providers/accounts/models are global; tools consume references. Aggregate and subscription modes keep upstream secrets centralized. API direct mode may write the selected API Key only through explicit preview/export/apply actions; never export rotating OAuth tokens.
- Preserve localhost-only binding. Do not edit existing Agent or CPA configurations on startup; config application is an explicit user interface action with backups and validation.
- Never log credentials, request bodies, or OAuth token material. Do not check real tokens, SQLite files or fixture data directories into Git.
- JetBrains Chat SSE uses a bounded 32 MiB buffer until the upstream reply is complete because the tested Koog client treats premature EOF/RST as success. Invalid/error/truncated streams must return HTTP errors before sending 200. Keep this behavior scoped to JetBrains. Preserve native Chat reasoning history; when converting Chat to Responses, omit display-only assistant reasoning_content instead of inventing native reasoning items or elevating it to an instruction. Document the buffering latency and history limitation.
- Use meaningful mock-upstream tests for auth, routing, stream cancellation, OAuth rotation and configuration preservation. A model listing is not an inference test.
- Run `npm run typecheck`, `npm test`, `npm run build` for relevant changes. Inspect the Electron-rendered UI when changing layout. Record native Windows/Linux and live-provider verification separately.
- Keep the usual Windows directory delivery at `release/win-unpacked` current. If a running app requires a separate versioned build, report its exact path and only sync the usual directory after its processes have exited; never terminate the user's app just to replace a package.
- Supported tools are Codex, Claude Code, OpenCode, DSH, VS Code Copilot Chat, GitHub Copilot desktop/SDK, and JetBrains AI Assistant in WebStorm, IntelliJ IDEA, Rider and PyCharm. Keep client-specific capability boundaries explicit; config serialization is not inference validation.

- Every tool exposes the same explicit “使用聚合接口” switch. Aggregate mode uses one localhost tool-scoped endpoint with selected sources and an exact model allowlist; direct mode uses one source and prefers a native API endpoint where the client protocol matches. Subscription credentials remain in the main process. Switching aggregate off keeps the default model’s source, falling back to the first source; switching it on preserves current sources and model selection. Preserve legacy automatic/multiple-native connections until an explicit mode change; do not apply external client settings on startup.

- Claude Code supports single-source direct mode and multi-source aggregate Messages mode. Use known official Anthropic-compatible API endpoints with the existing provider key; use the localhost Messages bridge for account subscriptions and other compatible sources without exporting OAuth tokens. Reuse configured models, use upstream IDs for native calls and aliases for the bridge, publish only enabled aggregate models, honor CLAUDE_CONFIG_DIR, and preserve unrelated settings. Privacy controls default on but are not an OS sandbox; MCP and native usage import remain explicitly unsupported. Terminal configuration does not prove IDE extension configuration or real upstream acceptance.

- JetBrains IDE model bindings are independent. Aggregate mode uses one localhost tool-scoped OpenAI-compatible endpoint; single API sources use a native Chat Completions endpoint when all selected models use that protocol, while Responses and subscription sources use the localhost protocol bridge scoped to that source. User changes to providers, connection mode or default/aggregate model selection may trigger automatic settings sync with backups. Running or unknown IDE states keep only the latest pending choice and recheck every 15 seconds, applying it only after a compatible stopped IDE is confirmed. Never create or replay automatic write requests on app startup or navigation; empty/disabled selections cancel pending writes, and failed writes require a new user action instead of blind retries. Explicit sync remains available. Both automatic/explicit settings sync and restore require a discovered supported 2026.2 / build 262 profile and a confirmed stopped IDE; running/unknown states provide manual connection parameters. Never read/write PasswordSafe or export OAuth tokens. The connection API Key must be pasted in the IDE separately and updated when switching sources or connection mode, and file sync is not an authorization or inference test. Preserve unrelated XML and backup/restoration history. This scope covers AI Assistant model settings, not Junie, Claude Agent, Codex, Gemini CLI, completion, MCP, Skills or IDE session imports.
