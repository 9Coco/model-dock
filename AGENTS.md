# ModelDock development

## 反代架构强制要求（用户明确要求）

- **ModelDock 托管的所有账号反代和协议转换，必须使用 Electron 主进程内的 TypeScript 适配器，并接入现有 Gateway。** 新增供应商、修复、重构、兼容处理和发行打包都必须遵守这一要求。
- **禁止引入或恢复 Docker / Docker Compose / 容器反代、Python / Pi 反代、独立 Node.js 或其他语言的反代进程，以及额外的账号 HTTP 服务或监听端口。** 不得以临时兼容、备用方案、可选依赖或后台服务的名义绕过。
- 供应商差异集中在现有主进程适配器中，复用已有认证、网络会话、模型目录、额度查询和网关路由；界面只通过窄 preload 接口调用。流式增量、取消和背压必须沿现有链路传递，凭据保持主进程加密存储。
- 这一约束旨在避免额外进程、容器及多层中转增加请求开销和延迟，避免引入环境部署、依赖、端口与进程生命周期的维护负担，也避免重复实现协议与认证逻辑，造成代码冗杂。
- 上游协议或能力尚未核实时，应明确说明暂不支持并保留原有账号与配置，不得暗中回退到外置反代。构建和评审应确认生产入口及发行包不包含或启动上述反代运行时。
- 本约束针对项目托管的反代运行链路。既有的一次性官方客户端授权导入、系统钥匙串读取，以及用户显式配置的外部 API 接入可以保留；这些能力不得被用来承载独立的托管推理反代或协议转换服务。

## 其他开发约定

- Keep app logic in TypeScript and the UI in React. The gateway and credentials live in the main process, with a narrow preload bridge.
- Providers/accounts/models are global; tools consume references. Aggregate and subscription modes keep upstream secrets centralized. API direct mode may write the selected API Key only through explicit preview/export/apply actions; never export rotating OAuth tokens.
- Preserve localhost-only binding. Do not edit existing Agent or CPA configurations on startup; config application is an explicit user interface action with backups and validation.
- Never log credentials, request bodies, or OAuth token material. Do not check real tokens, SQLite files or fixture data directories into Git.
- All managed account adapters are TypeScript in the existing main-process gateway. Do not launch Docker/Python/Pi relays or extra account listener ports. Preserve exact identity/license/workspace boundaries; unsupported account types require an explicit supported import, never an implicit personal-license fallback. Native credential snapshots stay encrypted and must never enter renderer/provider API keys/config exports.
- Forward streaming content/reasoning/tool deltas immediately with cancellation and backpressure for every client, including JetBrains. Retain only bounded terminal frames until complete validation; enforce size limits with counters, not a whole-reply buffer. Before the first event, invalid streams fail with HTTP errors; after output starts, failures terminate the stream and must not emit success/DONE or retry inference. Older Koog clients may display premature EOF as success, so record real IDE acceptance separately. Preserve native Chat reasoning history; converting to Responses omits display-only assistant reasoning_content without inventing native reasoning items or promoting it to instructions.
- Responses sparse `*.added` text/refusal parts may contain only their type and initialize empty content. Do not require completed text at a start event; reject explicit non-string payloads and missing final text. Include real provider event shapes and the installed Koog serializer/client in verification; configuration writes or model listings do not prove Rider inference works.
- Use meaningful mock-upstream tests for auth, routing, stream cancellation, OAuth rotation and configuration preservation. A model listing is not an inference test.
- Non-JetBrains binding edits save immediately and debounce external configuration writes for 400 ms. Keep only the latest pending selection per tool and serialize against main-process write locks; manual sync flushes the queue, undo/restore cancel it, and failures require a new action. Never enqueue on startup or navigation. Preserve one encrypted checkpoint of the last successful material sync, including affected files, ownership and selection; refuse undo after external edits, and roll back partial failures. Copilot undo uses native registry and exact system credential snapshots rather than direct SQLite edits. JetBrains keeps its existing offline pending-sync flow.
- There is no global model-directory page or local usage-statistics feature. Keep model configuration and discovery within each supplier and retain models needed for routing, while removing local token collection, pricing, history imports and their IPC. Protocol usage fields and subscription-account quota information remain part of their respective API/authentication contracts. Do not delete existing historical database tables merely because the statistics feature was removed.
- Run `npm run typecheck`, `npm test`, `npm run build` for relevant changes. Inspect the Electron-rendered UI when changing layout. Record native Windows/Linux and live-provider verification separately.
- Keep the usual Windows directory delivery at `release/win-unpacked` current. If a running app requires a separate versioned build, report its exact path and only sync the usual directory after its processes have exited; never terminate the user's app just to replace a package.
- Supported tools are Codex, Claude Code, Junie CLI / IDE ACP, OpenCode, DSH, VS Code Copilot Chat, GitHub Copilot desktop/SDK, independent Copilot CLI, and JetBrains AI Assistant / Air in WebStorm, IntelliJ IDEA, Rider and PyCharm. Keep client-specific capability boundaries explicit; config serialization is not inference validation.

- Copilot CLI has an independent multi-provider native/aggregate binding. Merge only its owned stable modeldock-<provider-hash>-chat / modeldock-<provider-hash>-responses entries (and legacy or aggregate modeldock-chat / modeldock-responses entries) into the documented providers.json and the default model into JSONC settings.json; honor COPILOT_HOME and COPILOT_PROVIDERS_CONFIG. Preserve other sources, settings comments, internal config.json, accounts, permissions, MCP, Skills and sessions. Native groups are separated by provider and protocol, each with its own URL and credential; aggregate groups share one tool-scoped localhost endpoint. Keep their native protocols. Use real model IDs/Key for native direct and aliases/local Key for aggregation; never export OAuth tokens. Protect both files with private permissions, encrypted ownership history, atomic rollback and unified undo; native desktop registry synchronization remains separate. Do not guess legacy internal config fields or claim old CLI versions support the named-provider schema without verification.

- Junie supports multiple discovered model profiles with Chat Completions or Responses. Synchronize every selected model to a stable JUNIE_HOME/models/modeldock-<model-hash>.json using its full inference URL and native apiType; keep modeldock.json as a clearly labeled current-default shortcut, merge only config.json's model selection, and register the owned Junie · ModelDock agent in ~/.jetbrains/acp.json with an explicit --model custom:modeldock. Preserve other profiles, agents, MCP, account material and settings; protect the default profile, all model profiles, config and ACP files with encrypted history, ownership checks, transactional rollback and unified sync undo. Preserve and migrate legacy three-file history. API profiles use independent native URLs/IDs/keys; subscription profiles use the existing Gateway without exporting tokens. On Windows resolve the official managed native executable instead of passing a .bat to the IDE. Never describe this ACP agent as the IDE's built-in Junie: built-in Junie BYOK accepts official OpenAI/Anthropic keys entered in the IDE and is not configured through custom profiles or PasswordSafe writes. Do not import Junie sessions, MCP or Skills as part of model configuration.

- Every tool exposes an explicit “使用聚合接口” switch. The configured Codex active connection, Claude Code environment and the four JetBrains AI Assistant OpenAI-compatible slots are single-entry surfaces (Air accounts remain a separate manual multi-account UI): native supplier direct means exactly one protocol-compatible API source and its native URL, real model IDs and API key, never a local-managed fallback. Aggregate means exactly one localhost endpoint; provider/model multi-selection belongs only to that aggregation interface internal mapping. Keep direct and aggregate choices separately, preserving exact empty mappings and inactive drafts safely. Other clients retain their existing connection capabilities. Subscription credentials remain in the main process. Mode switching restores the independent draft; unavailable native sources stay disabled and do not fall back to localhost. Strict-client legacy metadata may migrate to direct/aggregate while retaining references; do not apply external client settings on startup. OpenCode TUI/Desktop, VS Code, DSH, Copilot app, Copilot CLI and Junie support multiple native sources with aggregation on or off; changing mode must not truncate those selections. Use the shared product-capability table in UI, resolution, persistence and migrations. Preserve legacy metadata and inactive drafts without startup client writes.

- OpenCode TUI and Desktop support multiple providers with aggregation both on and off. Adding a provider must preserve existing selections; deselection removes only that source. Native connections use stable per-provider entries with separate API credentials and upstream model IDs; subscriptions use the existing main-process Gateway without exporting OAuth tokens. Toggling aggregation preserves selected sources, exact model filters and the default model. Do not truncate OpenCode selections or disable them during save, startup migration or reference cleanup merely because more than one provider is selected. TUI and Desktop retain independent bindings while respecting their potentially shared external config file.

- Claude Code supports single-source direct mode and multi-source aggregate Messages mode. Use known official Anthropic-compatible API endpoints with the existing provider key; use the aggregate localhost Messages bridge for account subscriptions and other compatible sources without exporting OAuth tokens; subscriptions and incompatible API protocols cannot be selected as native direct sources. Reuse configured models, use upstream IDs for native calls and aliases for the bridge, publish only enabled aggregate models, honor CLAUDE_CONFIG_DIR, and preserve unrelated settings. Privacy controls default on but are not an OS sandbox; MCP and native usage import remain explicitly unsupported. Terminal configuration does not prove IDE extension configuration or real upstream acceptance.

- JetBrains IDE model bindings are independent. Aggregate mode uses one localhost tool-scoped OpenAI-compatible endpoint; native supplier direct uses exactly one verified Chat API endpoint and upstream model IDs. Known official dual-protocol providers may project their existing Responses model metadata to native Chat without mutating global models. Unknown Responses-only services and subscriptions require a compatible aggregate interface; never silently use a local single-provider bridge in direct mode. User changes to providers, connection mode or default/aggregate model selection may trigger automatic settings sync with backups. Running or unknown IDE states keep only the latest pending choice and recheck every 15 seconds, applying it only after a compatible stopped IDE is confirmed. Never create or replay automatic write requests on app startup or navigation; empty/disabled selections cancel pending writes, and failed writes require a new user action instead of blind retries. Explicit sync remains available. Both automatic/explicit settings sync and restore require a discovered supported 2026.2 / build 262 profile and a confirmed stopped IDE; running/unknown states provide manual connection parameters. Never read/write PasswordSafe or export OAuth tokens. The connection API Key must be pasted in the IDE separately and updated when switching sources or connection mode, and file sync is not an authorization or inference test. Preserve unrelated XML and backup/restoration history. This scope covers AI Assistant model settings and independent AI Completion settings; it does not cover independent Junie, Claude Agent, Codex, Gemini CLI, MCP, Skills or IDE session imports.

- Windows JetBrains profile selection uses installed product metadata and public launcher/JVM evidence. Retained old profile folders, stale PID files, Toolbox and normal build daemons are not an open IDE. Do not guess a target by mtime. Missing identity or custom-path evidence blocks writes; distinguish that reason from an actually running IDE in UI and automatic-sync state. Recheck OS process evidence immediately before each offline write, and keep older profiles unchanged. Chat models and native FIM completion candidates are separate lists; show their counts, and treat unverified completion capability as unknown rather than claiming the model cannot support it.

- AI Completion uses actual NextEditProviderSettings CDATA JSON in llm.next.edit.providers.xml, not editor_model_id. Synchronize its URL/model/provider identity/schema with source changes; preserve unrelated parameters and apiKeyConfigured. Completion has a fixed independent PasswordSafe slot: endpoint/account changes or unsupported capability must set selectedProvider id/name empty and kind NONE before opening the IDE, never silently send the prior Key to a new source. Known DeepSeek native text completion uses /beta/completions and fim.generic; other suppliers must still get updated parameters but remain explicitly unsupported/off until verified. Do not convert Chat/Responses into fake FIM. Aggregate /completions is only available to the four JetBrains tools with the same local auth and exact active model allowlist. Cap known FIM outputs at 4096, using actual string-valued IDE budgets; keep native completion choice separate per mode without changing global model protocols. Current Generic architecture only sends prefix; actual class/localhost tests do not prove live editor or provider acceptance. Maintain legacy v1 three-file history and v2 four-file history/transaction rollback without inventing old completion baselines.

- Each JetBrains IDE stores its own selected plugin target, defaulting to AI Assistant. Target switching saves only that preference and cancels pending automatic synchronization; it must not write either plugin's files immediately. Provider/model choices remain the IDE's existing selection. Assistant keeps its established llm.* configuration, completion, offline synchronization and restore behavior. Air is a manual native Accounts flow: show More Providers → OpenAI, URL/Key/reference-model copy, preview and export; do not enqueue Air automatic synchronization or expose native-file apply/restore controls. The installed Air Accounts list filters metadata entries without PasswordSafe keys, so metadata-only other.xml edits do not produce usable editable accounts. Never write Air account files or PasswordSafe; users create/edit/remove accounts in Air and choose Agent/model/authorization there. Preserve Assistant settings when Air is selected, and do not claim copied parameters prove authorization or inference.

## FlowBridge 网络整合（0.4.0）

- ModelDock 的应用控制、设置与 UI 仍为 TypeScript/React。`resources/flowbridge` 中的 GPL 网络组件仅处理系统代理、TUN 权限/路由、TCP 字节转发与公开网站探测；这是系统网络层，不是账号或推理适配器。绝不把账号凭据、模型请求参数或工具配置传给它，亦不在其中增加账号 HTTP 服务。
- 所有连接/模式切换/取消由 `FlowBridgeManager` 串行管理；设置保存不隐式连接，只有已连接会话的显式设置变化会先恢复再重连。默认不启动网络组件；自动连接必须已显式开启。退出必须等待系统清理确认，失败保留程序和恢复记录供重试。
- 保留原 ModelDock 数据目录、SQLite 表、加密、Gateway 和 app.settings。新增网络设置使用独立 managed-state key；网络字节历史不等于模型 Token/usage 功能。独立 FlowBridge 的旧设置、服务、数据库不自动导入或覆盖。
- 组合发行版 GPL-3.0-or-later，旧 ModelDock 代码继续保留 LICENSE-MIT；资源保留独立许可。新增复制/修改内容更新 resources/flowbridge/manifest.json 的固定来源和哈希。
- 运行 `npm run test:network`、`npm run network:verify` 和 network-only Electron smoke。真实 Windows/Linux 路由、UAC/Polkit、手机 UDP、开机启动与崩溃清理须独立记录；模拟测试不能宣称系统接管已验收。
